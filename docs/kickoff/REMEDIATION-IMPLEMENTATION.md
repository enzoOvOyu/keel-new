# Kickoff 设施、增量发布与分域 Agent 整改

状态：已部署前端ef08c25 / API aabae08。编译、设施发布基线定向单测和三页只读界面检查通过；真实Agent/入库验收等待用户指令。

## 验收边界

- 机房机柜保留四类输入模型，最新UI采用单一清单/详情抽屉及按需输入入口。覆盖率按真实字段及关系计算：机房归属、机柜容量、设备高度、U位、可完整落位、空间坐标；每项可筛选缺口。空柜/无设备引用不是废弃判据。
- 关系字段使用稳定ID，选择时展示名称与识别信息。支持批量归属、容量尺寸、型号高度和明确行列间距坐标；先显示影响范围和冲突，默认只补空白。
- 正式机柜图仍读取CMDB，不复制画布；未发布预览不得冒充已发布图。
- publish保留范围选择与确认按钮，支持设备/设施独立增量；连接可引用项目内已发布对端。正式事务重新验证身份、端点、修订、幂等、Outbox和回执。
- 结果区分身份入库、已知位置关系、精确落位和空间能力，不将部分数据标为全部绘制完成。observed和人工确认事实保持保护。
- Agent复用既有Parser、Provider、持久任务和MinIO产物，按域读取证据并生成候选。每个区域有覆盖结果；缺失不伪造。候选经人工采用，不直接发布CMDB；已有人工输入不被自动覆盖。

## 实施证据

- publish：原API新增facilityIds；设施独立比较/发布、祖先闭包、同项目既有端口引用与连接差异基线。UI增加设施范围和发布后能力变化，保留确认按钮与弹窗。
- facility：FacilityPanel、FacilityBatchEditor、FacilityEntities复用现有四表与UI，真实覆盖/筛选、机柜状态、友好稳定引用、批量影响预览和空值补齐；正式机柜图仍读取CMDB。
- Agent：新kickoff_agent*.go复用eng_job和MinIO，新增域参数、候选读取和人工采用；SourceAgentPanel接入API，原五栏及区域预览采用真实Agent证据。原Provider/Parser和工具框架保留，无第二队列。
- 契约：OpenAPI、生成类型、Go服务、前端Adapter、模块API台账同步。最终TypeScript类型检查、Go编译、API文档引用及diff检查通过；运行/交互与真实模型验收未执行。
- 真实模型调用、实际CMDB入库与端到端测试NOT RUN。三页只读显示检查通过，发布证据见DEPLOYMENT。
- 限制：仅XLSX；历史旧StepInputCatalog草稿不自动转换；首次新Agent分析不能冒称历史已完成域已无模型成本。缺依据仍需用户补充，不承诺任意资料全部自动识别。

## 明确U刻度与区间

设施提取增加受限归一化：`u_scale_capacity` 仅用于racks.capacity_u，要求原件完整、明确的1..N或N..1 U刻度及来源标识，局部截断/普通序号/公式缓存/行高/边框不能推定柜高；`u_range_start/u_range_height`仅用于明确带U标识的区间。算法由本地执行，候选仍需确认；保留刻度、表头、范围和归一化证据。不声称已完成MM落位图识别验收。

## 用户纠偏后的交互整改

机柜清单替代满屏卡片，详情抽屉编辑归属与规格；四类表格不再作为底部重复工作区。机房布局以实际排数、每排数量、尺寸、净距、通道和机房边界距离输入，生成中心点平面位置，保留高级参数。相同尺寸/朝向按组设置，已有位置默认保留，不推断真实距离。型号高度只补空，不因其他实例不同高度阻断。

发布统一增量列表，不单独设设施卡片。设备与设施为既有API可选择根对象；依赖按类查看、按需加载，变化判据与最终范围仍由服务端核对。弹窗冻结选择与统计；版本比较找实际上一记录。独立设施基线传播修复通过定向单测，未运行真实发布。

Agent操作收进五步右侧；局部分析范围按需打开，候选显式审核采用不变。用户要求中止当前分析，已将对应任务置USER_CANCELLED并撤销claim，由原心跳取消执行上下文；没有新增模型调用。

最新用户纠偏：入库主区不展示端口/精确落位等包含数量统计，默认仅新增/变化根对象，依赖按类别查看；原确认弹窗数量保留。

缺口补录整改ef08c25：主区显示明确缺口与直接操作，自动带入对象；型号高度集中补录，位置表只带缺项设备；完整清单/导入/布局按需展开。TypeScript、Vite及两类只读补录弹窗检查通过；无实际保存/AI/发布写入，API未重启。
