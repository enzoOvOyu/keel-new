# 智能开局：关系推理 Agent

## 本轮目标

仅围绕工程资料中的真实设备、双端端接、机柜/U位和线缆关联。复用现有 Provider、Workbook IR、持久任务、MinIO checkpoint、人工采用及工程模型。没有新数据库、菜单、独立导入流程或自动CMDB发布。

## 已实现

1. 在分域提取之前增加独立 `reason_relationships` AI 调查阶段。AI 为来源区域作对象性质判断（设备、组件、物料、汇总、连接、落位、未知），提出跨表身份假设，给出来源坐标及简短依据；未判断为设备的区域不允许输出设备候选。
2. `find_related_records` 按来源单元格在完整本地工作簿检索相关记录，返回脱敏的行上下文及坐标；检索命中不等于设备身份成立。
3. `evaluate_relationships` 对 AI 提出的关系执行全行检查，支持多张清单、同一记录的多个别名列，以及有来源佐证的逐行AI别名判断。唯一匹配、未匹配、冲突分别统计；重复引用同一身份不会制造多台设备。未经工具检查的关系不能作为最终计划。
4. 端接两端通过已检查关系绑定到 AI 判断为设备的清单来源。删除“仅凭连接中的SN自动补造设备”的投影行为。原有端口投影只服务于已有明确设备候选。
5. `verify_workbook_formulas` 复用现有隔离计算Provider，整本核算一次后在本地使用文本及数值结果。此前通用工具只返回32条并移除文本结果，不足以承载公式生成的设备名称/线缆型号。本工具走本地结果通路，模型只得到数量和状态，真实文本不出现在工具响应；计算结果保留run引用。未兼容计算结果仍不能替代缓存进行关联。
6. 连接候选包含可选 cable_model、cable_length_m、medium、两端optic model。人工采用时线缆关联具体连接，复用CablePlan及稳定ID；长度存Estimated，不覆盖As-built；两端光模块保留来源证据，不虚构模块数量。已有连接可补空字段，冲突保留已有值，多段线缆/配线复杂路径不自动选段。
7. 关系坐标和简短依据进入候选字段证据；物理采用保留跨表佐证。任务日志记录对象判断和关系假设，现有证据抽屉显示依据。未重新设计前端。
8. 起始U和设备高度缺失分开报告，保持原PLACEMENT_U_REQUIRED代码，避免“有U位但缺高度”被描述成没有U位。

默认“开始/重新分析”仅选择设备、设施落位和布线三个域；其他域仍可在现有分析范围中显式选择。

## 执行与边界

关系调查最多18次工具调用后输出最终结论；不允许因调查失败静默退回旧表头提取。旧解析候选不会被本次部署自动删除、重算或采用；新提示及契约版本更新checkpoint指纹，旧映射不能冒充新版推理。

所有结果仍是未确认候选。AI佐证不是人工审批，也不能保证所有别名必然判对。冲突和未匹配行保留，公式不支持时明确缺口，不编造身份、位置、长度或单位。
