# BOM Intelligence Agent · AI 开局规划工作台

本节是 FR-2.1 的当前实施增补，替换此前本文件的 AI/固定模式双入口。当前只实现 AI 智能识别；不新增固定模板、字段配置流程或对应页面。历史批次与既有正式 BOM 保留。唯一 bom_item、项目授权、资产身份、事务 Outbox 和六阶段交付链不变。

## 四阶段交互

1. **上传开局规划**：显示当前项目、拖放/选择文件、大小、移除待上传文件、上传并开始分析、最近批次和系统 AI 配置链接。无需填写映射规则。支持 XLSX/XLSM（20MB），不声称支持 CSV/PDF/XLS；不执行宏、外部链接或公式。
2. **AI 分析进度**：显示持久化任务的工作簿检查、工作表/区域扫描、交换机/端接/其他提取、跨表引用、关系核对和覆盖审计。显示失败和继续未完成步骤；已完成方案复用，原文件不覆盖。AI 未配置/失败仍保留程序解析结果，明确识别未完成。
3. **分类审核**：全部、交换机、端接与线序、服务器、网卡、光模块及连接介质、电源及机柜、其他、无法识别。交换机与连接优先排序。紧凑 DataTable 支持搜索、类别/状态/来源筛选、分页、选择、单条编辑确认、批量确认、公共字段修正、排除与恢复、选中内容重识别。使用一个 Dialog 查看原始单元格、公式与缓存、来源字段、差异和问题，不嵌套详情。交换机查看端口清单；端接展示 A 端设备/原始端口 → 线缆 → B 端设备/原始端口，缺项突出。源文有配线架时保留，不推测中间跳接。
4. **确认入库**：冻结项目/修订/记录集合，仅已确认且通过独立确定性校验的闭合依赖集合能提交；剩余候选保留。展示正式 BOM revision、逐条结果、CMDB Outbox 发布状态。上传、识别和人工确认均不是正式入库。

## 主 Agent 与工具

继续使用 Go 模块化单体。既有 Excelize 解析适配器生成唯一 Workbook IR，保留所有 Sheet、单元格、坐标、隐藏信息、合并区、样式 ID、公式与保存时的缓存值。没有新增 Python 业务后端。Pydantic 作为受控 JSON 校验进程，仅通过 stdin/stdout 验证模型提取方案，不访问数据库/网络。

单一 `runRecognition` 编排器调用工具：

| 工具 | 实际处理 | 结果/边界 |
|---|---|---|
| inspect_workbook | 扫描 IR 的非空来源及连续区域 | 全部工作表、有效区域与数量 |
| analyze_sheet | 读取 IR 结构并用全工作簿语义上下文规划 | Sheet 用途及有原始列绑定的方案 |
| inspect_region | 查询指定区域的真实单元格；采样前/中/后位置 | 后段表格不只依赖首行，未映射原文保留 |
| extract_switches | 按已检查的来源绑定提取交换机/端口 | 身份、原文规格、角色、位置、配置字段 |
| extract_terminations | 提取明确物理端点及介质字段 | 不把逻辑配置/汇总数量当物理线缆 |
| extract_entities | 提取服务器、部件与物料规划 | 同行可有不同对象，同一物料不能重复分类成多份 |
| cross_sheet_resolve | 解析真实公式引用，定位目标原始单元格 | 仅显式引用；不生成不存在的实体 |
| resolve_relationships | 唯一且精确的设备标签/来源别名/端口解析 | 不做名称相似匹配；歧义阻断 |
| audit_coverage | 独立对账 IR、保留来源与字段证据 | 逐区域保留/提取/未映射、候选/确认/未知/排除数量 |

模型仅接收必要脱敏结构和区域样本，不接收原始 Excel 文件；秘密排除，已识别身份列脱敏。简单字段值由程序读取，模型只提出来源绑定和语义类别。所有额外字段仍保存来源；置信度不是工程正确性。

## 重点正确性约束

- 设备标签、来源别名、型号、序列号、公式和表内辅助键分别处理。真实公式返回的设备标签可用于唯一匹配；计算辅助键/零值/错误值不能充当资产身份。
- 公式缓存不是新采集结果。不执行公式；缺少缓存保留待核查。公式原文从不可变 IR 按需读取，不在每个候选重复保存。
- 合并单元格仅在实际合并范围内继承所属设备，证据指向锚点；普通空白不自动向下填充。
- Cable Type 不等于速率、U Position 不等于机柜容量、Customer Rack Name 不等于机房。未给出的端口数/速率/长度/数量/型号不得从名称数字推断。
- 交换机身份使用明确设备标签，落位等不同名称保存为来源别名，不静默替代；原始端口名称保持原样，允许 Ethernet1/1/1、25G-1 等。
- 实物、有名称但无 SN 的规划设备、只有名称/规格/数量的 material_plan 分开，不能按数量制造设备。逻辑网络与物理连接独立。
- 需要模型审批、缺少端点/父设备/单位/安装尺寸、端口冲突的候选继续阻断，不能为显示成功而补造或放宽。
- 覆盖审计 complete 表示所有区域已分析且来源保留完整，**不是提取准确率或所有内容已识别**。未映射/无法识别内容独立展示，不自动排除。人工排除必须理由。

## API / 数据 / 断点

沿用 bom_import_batch.workbook/workbench、bom_job、ai_task、bom_submission。`workbench.steps` 记录真实工具调用；`workbench.coverage` 为独立扫描对账，详见 OpenAPI BOMAgentStep/BOMRegionCoverage/BOMCoverageAudit。记录仍引用现有 BOMDraftItem/BOMSourceCell，不建另一套资产表。

- 上传：`POST /projects/{project_id}/bom-imports`，当前页面仅发送 import_mode=ai。
- 进度：`GET /bom-imports/{id}/workbench/progress`，只返回持久化任务元数据、候选数量、Sheet 状态、覆盖清单及最近 16 条步骤；不返回候选/源单元格，不运行工程校验。
- 结果：用户进入第三步时按需读取 `GET /bom-imports/{id}/workbench?compact=true`，单条完整证据用 record_id。列表原始描述缩略，原文不修改。分析完成后保留当前页面，由用户点击进入审核。
- 修正：`POST .../workbench/records`，revision/record_ids/action=edit|confirm|ignore|restore，修正/排除必须理由；修正撤销原确认。
- 校验：`POST .../workbench/validate`。
- 分析：`POST .../workbench/recognize`，空 record_ids 继续未完成任务；指定记录重新分析其来源。成功方案重新读取原始单元格，不重复请求模型；无效方案携带具体错误反馈修正一次。人工修正和已导入记录不得被恢复覆盖。
- 提交：`POST .../workbench/submit`，revision/record_ids/acknowledge_warnings/Idempotency-Key；后端复验权限、依赖和当前事实，原事务 BOM+CMDB+Outbox。
- 发布：现有 publication 查询；提交和发布状态分开，失败可重放。

加载：上传结构解析和 Outbox 期间 Poll 2s，识别期间仅 progress 接口 Poll 4s，禁止轮询整份候选；其他按需。项目由资源和后端授权确定，不相信前端筛选。AI 失败不自动切换固定模式，不写正式 CMDB。

## 运行与验证边界

Pydantic 环境安装 `dev/backend/tools/requirements.txt`，设置 `KEEL_BOM_PYTHON` 为该环境 Python 路径。缺少校验器必须显式失败，不跳过 Schema 验证。

当前验证范围：必要编译、公式/合并来源/覆盖遗漏/重复提取的定向检查，以及用户两份真实文件的候选结果核对。用户已明确接管完整导入、CMDB 发布和跨模块闭环测试，不重复执行端到端脚本，不以历史报告作为本轮通过证据。尚无人工标注完整基准，不报告模型准确率。

当前边界：自由文本/图形颜色表达而无法形成可靠来源绑定的内容保留为待识别；未实现视觉模型区域截图、LibreOffice 重算及自由绘图路径提取。未知内容不可宣称已完整识别。

当前实现边界（2026-10-31）：Sheet 规划已接入最多 8 轮的只读工具选择与纠错，支持按区域补查和追溯跨表引用；提交方案经过独立来源覆盖与历史绑定校验。整体任务调度、分类、关系解析、人工确认和正式入库门禁保持程序控制。真实多轮复测仍有错误模型回答被拒绝，不能将覆盖 complete 或候选保留等同于识别准确率。用户已暂停重复复测并接管后续验收，详见 BOM-AGENT-CORRECTNESS-20261031.json。
