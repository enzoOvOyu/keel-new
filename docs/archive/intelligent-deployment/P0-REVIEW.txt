二、数据区域和公式依赖
典型多区域：
- 电力测算：A4:D14设备功率/数量，A16:B18容量参数，A20:N79每柜负载，A81:B84总计。
- 距离计算公式：A:D点位坐标，F:G区域配对距离，I:J参数，L:M必经点，
  O:P特殊路线，R:AE逐路径结果。同一Sheet横向多个独立区域。
- 落位图：1:53、60:112、119:171三段网格，合并格参与表达空间和占位。
- 工作量：A:H线缆规格/长度数量，与K:M设备/U数/安装量并列。
- 布线明细：端接/型号/标签与Q:T模块Key及首现标记同时存在。

关键计算链：
设备数量×功率参数 → 每柜负载/剩余容量 → 布局显示。
点位坐标+路径参数 → 路线选择/估算距离 → 标准长度 → 端口级连接展开。
设备端口 → 父物理端口去重键 → 模块需求 → 采购差额。
设备安装数+线缆规格/长度分布 → 施工数量；没有工时规则不推算工时。

P2P-18与距离计算公式存在Sheet级双向引用。代表性单元格链：
P2P-18!F2 → E2 → 距离计算公式!AE2 → 路径/坐标/参数 → P2P-18!C2/D2原始输入。
不能把Sheet级双向边直接判为循环依赖；本轮未完整展开单元格DAG或证明全局无环。

94,353个公式均有缓存且没有缓存错误单元格，但forceFullCalc=1。
IFERROR可能隐藏无匹配/缺输入；缓存非空、没有#ERROR不等于计算正确。
56项机柜负载和432项标准线长用独立Decimal算术对照缓存，均一致。
对照只证明这些运算与已存输入/缓存一致，不证明来源、单位、业务口径或引擎兼容。
本机未发现LibreOffice/soffice，没有进行Excel或Calc参考重算。

四、当前实现偏差
1. 目标仍是候选行入库，缺少完整工程模型和分域产物。
2. SheetPlan/PlanningContext不包含动态模块实例、输入依赖及分域发布计划。
3. 公式以缓存值参与映射，计算规则、输入输出依赖与运行记录没有独立建模。
4. 物理发布门禁直接影响规划候选，难以表达“意图可用，但确认链路缺速率证据”。
5. 大Workbench JSON及Item.Fields混装多领域，带来大结果保存和增量更新问题。
6. 记录级确认和部分提交不等于模块版本、规则版本独立审批发布。
7. CMDB虽已有planned来源层，UpsertAsset仍按incoming属性合并当前payload；
   规划与Observed的字段选择规则必须重新明确，不能假设已有fact_layer就完全隔离。
8. Coverage Complete主要证明来源保留和Sheet处理状态，不能证明工程语义识别完整。

八、业务依赖和发布
模块注册表声明输入、输出、依赖、适用条件、计算、校验、门禁、发布目标。
资料理解后由AI提出ImportPlan；可信执行器按输入/输出版本调度，允许独立模块并行。
模块状态覆盖NOT_APPLICABLE、DETECTED、NEEDS_INPUT、READY、PROCESSING、
IN_REVIEW、APPROVED、PUBLISHED、BLOCKED、STALE。
缺资料不等于NOT_APPLICABLE；故障只阻断依赖它的结果。
输入/参数/规则改变，使依赖计算、校验及审批STALE；生成新版本diff，不覆写人工确认。

发布出口：
- 设备/组合/位置/端口/连接的planned版本 → 现有CMDB与机柜图。
- CablePlan/PowerPlan/MaterialEstimate/WorkloadEstimate → 工程域版本。
- 审核后的NetworkPlan Revision → Golden（具体消费契约待确认）。
保留事务Outbox；独立发布记录绑定模型版本/审核决定/目标与幂等键。

建议首条纵向链：设备及组合 + 机房/机柜 + RackPlacement → 校验/审核 →
planned发布 → 现有机柜图读取。后续按用户指定的连接、电力、采购、网络批次推进。
P0/P1完成前不开始这条链的业务实现。
