# BOM 开局配置布局调整

依据 DESIGN-SYSTEM §2、§5.1 和 UI-REFERENCE §4，保留现有真实 API 与六步业务流程。

```text
页面标题 / 项目上下文                         [返回导入记录]
①上传解析 → ②Sheet识别 → ③字段映射 → ④BOM预览 → ⑤工程校验 → ⑥审核提交
批次文件 / 状态 / 当前版本 / 来源摘要
┌ 上传：文件选择与主要动作 ──────────────┬ 导入设置与处理说明 ┐
└─────────────────────────────────────┴───────────────────┘
导入记录（独立目录与筛选）

映射：Sheet / 原始字段 → 标准字段与转换 | 折叠：AI诊断、型号确认
人工候选修正：字段网格 / 来源追溯 / 双端关系 → 保存修订
校验：问题筛选 / 执行校验 / CSV；点击问题返回修正
审核：版本与数量摘要 / 警告确认 / 审核 → 提交 / 发布结果
[上一步]                                  [下一步：阶段名称]
```

步骤导航使用轻量状态，不与执行按钮竞争；区域最多一个主操作。只调整展示和布局，不更改解析、审核、提交、权限和版本契约。

## 实际验证

- 浏览器检查1440/1280宽度：文件选择、六步切换、映射工具、校验与审核页可用，无页面横向溢出及脚本错误。
- 未审核批次提交禁用；未执行校验显示“尚未完成工程校验”，不以零问题代表通过。
- 复用 bom-workbench-check.mjs 完成合成文件上传、字段映射、双端人工修正、校验、审核、真实提交及 CMDB 发布，结果 PASS。
- 生产构建通过；后端与 API 契约未变更。
