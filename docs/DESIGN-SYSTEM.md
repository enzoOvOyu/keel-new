# Keel Design System — 智能开局工程原型视觉基准

> 当前统一方向（用户确认，2026-11-03）：以 `kickoff/` 智能开局工程高保真原型为全平台后续前端开发和页面改造的视觉基准。统一颜色、字体、密度、布局节奏、控件、Drawer、弹窗及状态反馈；各业务保留自己的信息架构、交互和数据语义。本次只更新规范，已有页面是否完成迁移以实际实施记录为准。
>
> 本文件的通用视觉规范优先于下方历史增补中的旧颜色、字体、间距及“保持原主题”描述。作业平台继续按§10复用Kestra原生组件和专业交互，通用视觉通过主题及组件适配对齐本规范；组件来源要求不再构成另一套通用视觉标准。既有App Shell、Router、ProjectContext、RBAC和业务权限继续复用。

## 2. 视觉语言与设计令牌

### 2.1 整体风格

浅灰页面底承载白色工作区，以细边框、轻分隔和字号层级组织内容。绿色用于主动作、选中项和有依据的就绪状态。数据表和编辑区是主体，建议动作、问题、版本及来源放在清晰的辅助区域。

- 同一操作区域一个主按钮，其他动作使用描边、ghost或文字链接；按钮动词表达业务结果。
- 统计采用一个横向统计条及内部分隔线；统计项本身透明、无独立阴影。按页面需要决定是否显示及显示几项。
- Section用来界定独立任务或数据集合。已有Section内的表格直接铺满工作区，不再套一层默认Card。
- 总览可用浅绿Banner和建议动作面板；说明控制为短句。详细规则、来源和计算过程按需展开。
- 表格密集页、拓扑画布和执行编辑器保留各自结构，统一其外围控件与视觉层级。

原型提供浅色基准，未提供完整深色对照。已有主题切换继续保留；后续适配通过现有语义token覆盖背景、文字、边框与状态，需单独核查可读性，不用CSS反色，也不把浅色截图当作深色验收。

### 2.3 字体与信息层级

正文栈：`Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。数值标识、SN/MAC/IP、端口名、字段键使用现有`KeelMono`（JetBrains Mono）与等宽fallback；复用已托管字体。

| 元素 | 基准字号 / 字重 | 规则 |
|---|---|---|
| 工作区默认 | 13px / 400 | 局部说明、表格按下列层级覆盖，不继承旧页面的大行高 |
| 页面标题H1 | 26px / 650 | line-height 1.35，letter-spacing -0.7px |
| Section标题H2 | 15px / 650 | 建模内容标题按原型页面的层级；侧栏小区块可用12px |
| 子标题H3 | 13px / 600 | 只用于真正的内容分组 |
| 页面说明 | 12px / 400 | line-height 1.6，距标题9px |
| 区块说明、元数据 | 10–11px / 400 | 区块说明line-height 1.5，关键值不放入最弱层级 |
| 按钮 / 表格正文 | 11px / 500、400 | 按钮line-height 1.3 |
| 表头 / 状态徽标 | 10px / 500 | 状态短文案，不撑高整行 |
| 统计数值 | 27px / 550 | label/detail 10px，数值上下间距7px |
| Eyebrow | 9px / 600 | letter-spacing 1.7px；仅作辅助分类，不能代替中文标题 |

不为套用组件默认值把所有正文放大到同一字号。双行名称单元格保留“名称 + 次要标识”层级，来源与长字段在Drawer中完整查看。

### 2.4 间距、边框和层级

- 常用间距为6/8/12/16/20/24/32px；以下组件的精确padding直接对齐原型，不能统一取整后改变密度。
- Section/统计条/Banner圆角8px，按钮6px，输入框5px，徽标4px；Modal 11px，Drawer贴右侧。
- 常规工作区为1px边框、无浮起阴影；主按钮仅保留极轻阴影。明显阴影只用于Modal、Drawer及Toast。
- 浮层视觉按现有Overlay统一管理：原型遮罩`#203f4252`与2px背景模糊，遮罩/面板/Toast顺序60/61/80。接入主应用时映射现有层级，不靠无限增加z-index遮住其他模块。

## 3. 页面布局与响应式

### 3.1 唯一Shell与内容区

沿用现有Sidebar、顶栏、项目切换器、Router和RBAC。Shell统一品牌和上下文，业务页面从内容区开始。后续Shell视觉迁移也遵循本文件，但业务组件不得自行复制导航、修改全局项目状态或覆盖其他模块布局。

- 原型独立Shell的侧栏226px、折叠68px、顶栏65px仅作Shell改造时的尺寸参照；挂载页面服从现有Shell布局。
- 标准桌面内容区padding `30px 32px 50px`，max-width 1900px并居中；只由一层容器负责外边距。
- Heading左侧为分类/标题/一句说明，右侧动作组；gap 20px、距主体25px，动作之间8px。
- Section标题区padding `20px 21px`，区块间距约20–21px；表格、分页和底部说明条沿Section边缘对齐。
- 原型统计条为一整条白底容器，padding `20px 0`，统计项左右23px及细竖线；数量按实际内容决定，不把所有页面做成五项。

### 3.2 按任务选用布局

| 页面类型 | 原型结构与基准宽度 | 保留的关系 |
|---|---|---|
| 总览 | 主区`minmax(0,1fr)` + 280px辅助栏，gap 21px | 主区给出数据/工程概况，辅助栏放建议动作、问题和近期活动 |
| 资料接入 | 245px资料列表 + 自适应资料区 | 文件 → 区域/工作表 → 识别状态与证据联动 |
| 数据核对 | 主表 + 265px问题栏，gap 20px | Tab/筛选/选择 → 对应问题 → 对象来源Drawer |
| 入库与版本 | 主区 + 290px辅助栏，gap 21px | 明确范围、影响和计数 → 确认 → 回执/版本差异 |
| 工程建模 | 224px输入目录 + 自适应输入表，gap 20px | 当前输入类别 → 版本/用途/来源 → 表格 → 编辑Modal |
| 拓扑/机柜/执行 | 保留已有专业画布或编辑器 | 工具栏、状态、证据Drawer沿用共同视觉；画布获得主要空间 |

这些是布局类型，不要求每个模块具有同样的统计卡、固定侧栏或工程步骤。

### 3.3 原型断点

| 视口宽度 | 内容调整 |
|---|---|
| ≥1650px | 内容padding `35px 42px 50px`；总览辅助栏315px、gap 25px；建模目录245px |
| 1351–1649px | 使用标准桌面值；1440px和1600px为主要对照宽度 |
| ≤1350px | padding `26px 23px 40px`，H1 23px；总览辅助栏240px，核对235px，版本250px，建模目录205px |
| ≤1100px | 总览、核对、版本主辅区上下排列；标题与动作可换行；建模目录185px |
| ≤760px | padding `22px 15px 35px`，H1 22px；资料/建模目录改为横向可滚动选择；表单单列、工具栏换行 |

较窄断点覆盖较宽断点。表格在自己的容器横向滚动，统计/流程条保留可读最小宽度并横滚；不把整页撑宽。Drawer最大95vw，Modal在桌面两侧至少18px、窄屏至少11px。现有Shell负责移动端导航。

## 4. 信息架构与复用范围

- 导航树、菜单可见性、URL和项目作用域沿用现有应用注册表；风格统一不新增一级菜单。
- 智能开局工程保持`/p/:projectId/kickoff/*`，九个页面作为现有入口的子菜单：启动总览、资料与识别、数据核对、入库与版本，以及机房/网络/装机/布线/电力五个建模工作区。
- BOM、CMDB、Fabric、Fleet、作业平台和管理设置各自保留当前职责。其他模块采用开局原型的视觉和控件模式，不复制其业务步骤或术语。
- 专业画布、五/八Tab资产详情、代码编辑器等复用既有实现；共享的标题、筛选、列表、反馈和浮层对齐本规范。

## 5. 页面规范

### 5.1 智能开局工程：完整样板

以[九个原型页面](../kickoff/src/pages)及[工程输入编辑器](../kickoff/src/components/ModelEditor.tsx)为准：

- 资料入口保留上传区、文件列表、区域选择、来源和识别状态。添加资料后有明确结果；分析未接入时显示实际限制，不能显示虚构完成。
- 核对页保持对象Tab、搜索/排序/分页、选择范围、问题侧栏和证据Drawer。点击对象查看关系，点击来源定位对应资料；未知值显示“待补充”。
- 建模页采用“左侧输入目录 + 右侧表格”，表头动作是导出/导入/编辑。输入用途、来源、版本保留在表格上方；不换成冗长的连续必填表单。
- 编辑输入使用宽Modal：模板下载/导入/新增行 → 预览与表头问题 → 采用到编辑区 → 编辑/删除行 → 应用输入。预览和正式应用是不同动作，保存完成后再关闭并刷新数据。
- 确定性布线/电力计算是可见功能区，展示输入依据、计算组成、结果分布、缺失条件和重算动作；缺输入时保留模块与补充入口。输入变更后展示真实stale状态。
- 入库页保留范围计数、留待处理项、用途、明确确认、回执和版本差异。只在真实回执完成后标记已入库；后置配置缺失不影响独立有效范围，按当前Kickoff契约展示。
- 布局和动作数量由具体页面承担的任务决定；旧BOM工作台的步骤/门槛不能作为新Kickoff的视觉模板。其他业务审核和权限规则仍以对应领域契约为准。

### 5.2 BOM 资产列表

虚拟化数据表；固定关键列（业务码/类别/型号/序列号/位置/状态/来源批次）；支持列显隐、筛选、排序、导出。详情抽屉显示身份、关系、来源、版本历史、审计和相关工单。不要把所有字段挤进表格。

### 5.3 网络设备与端口

列表显示 hostname/SN/角色/机柜/管理 IP/NOS/ZTP/配置同步/健康/最后采集。详情抽屉 Tab：基础信息、端口、配置版本、配置事件、运行状态、无损链路、光模块、日志。Tab 懒加载；异常优先，原始证据可下钻。

### 5.4 交付总览与门禁

显示网络阶段和 六阶段交付主链路 的独立状态、前置断言、证据新鲜度、责任角色和阻断原因。状态四值统一：PASS/FAIL/BLOCKED/WAIVED；WAIVED 必须显示批准人、原因和有效期。

### 5.5 执行详情

Overview（阶段时间线/汇总）、Targets（目标矩阵）、Logs（实时/历史日志）、Outputs（产物/渲染变量）、关联（BOM/工单/上游任务/版本快照）。大型目标表虚拟滚动；日志支持过滤、复制和定位，不默认加载全部历史日志。

### 5.6 Flow/配置变更/PushJob

使用明确的“目标范围 → 参数快照 → 预检查 → diff → 审批 → 执行 → 验证”步骤。危险操作显示目标数、版本、回滚策略和不可逆影响。执行按钮不得与预览按钮混淆。

| Toast | 底部24px居中；12px；padding `15px 17px`；圆角8px | 简短操作反馈，可关闭；持久错误同时保留在对应工作区 |

### 6.1 表格与编辑密度

- 采用TanStack Table/现有DataTable能力；搜索、排序、筛选与真实总数匹配。数据规模由API分页或虚拟化处理，不能在组件内生成假数据。
- 原型常规列表默认10条/页，建模输入预览8条/页，编辑器12行/段。作为密度参考；真实接口的分页协议继续生效，不把固定页大小变成产品约束。
- 表格保留关键身份/名称/位置/状态/来源；长说明、全部关系及原始证据放Drawer。名称单元格允许双行，次行弱化但可读。
- 选中行与当前查看对象明确区分；复选框、复制和行内动作不能误触发整行详情。
- 导入预览保留字段问题和未知列反馈；采用预览后仍可编辑。分页编辑不丢失其他页的输入，提交前展示本次作用范围。

### 6.2 Drawer与Modal

- Drawer用于查看、追溯和上下文内切换；宽Modal用于批量工程输入；已有专业编辑器保留独立工作区。不要为普通详情跳整页后丢失筛选。
- 复用Radix/既有Dialog的焦点管理、Esc和关闭行为。未保存修改在关闭/离开时确认，正常查看不增加多轮确认。
- 浮层必须挂到同一主题/样式上下文；在主应用中检查Portal仍继承字体、颜色与控件尺寸。原型页面CSS不能泄漏到其他模块。
- 保留已有唯一资产详情Drawer与五/八Tab，不为套用视觉样板复制第二套资产详情逻辑。

## 7. 状态、反馈和交互

- 原型颜色只是表现方式；loading、empty、error、permission、partial、unknown、stale及failure由实际API和权限决定。每种状态给出原因和对应下一步。
- 加载保留页面框架与上下文；为空说明可导入/新增/调整筛选；失败保留已填输入并给重试；技术诊断如request_id放可展开或可复制的辅助信息。
- 无权限操作按既定RBAC处理，页面说明原因；隐藏菜单不能替代后端授权。可点击操作必须有实际行为。
- 按钮提交期间显示忙状态并防止重复提交；“已排队”“处理中”“完成”分别展示。后台任务持续运行时，返回页面可读取原任务状态，不重新提交。
- 对象可部分就绪，缺配置和身份冲突分别呈现；状态条不能用总体绿色覆盖局部失败。用户可按来源定位问题。
- 未知显示“待补充/未知”；无关项显示“不适用”；已提供的0按数值和单位显示。规划、建议、人工确认、计算及观测保留文字来源。
- 输入变更导致计算过期时，就近显示原因和重算入口；保持历史结果/版本可查看，不把旧结果继续标成当前有效。
- 焦点环统一，图标按钮有标签，状态不只依赖颜色；表格对象可用键盘进入。遵守`prefers-reduced-motion`，过渡以150ms轻微背景变化为主。
- URL与现有状态管理保留当前项目、对象、Tab、筛选和返回位置；切项目取消旧请求/订阅，确认操作绑定实际目标范围和版本。

## 8. 后续页面迁移方式

1. 对照本文件和现有原型，确定页面属于总览、资料、核对、建模、版本或专业画布哪类结构；保留已批准页面的功能、信息层级与路由。
2. 优先在现有主题token及共享组件variant中统一颜色、字体、padding和状态；稳定的纯展示封装可复用或提取到现有共享组件目录，不让其他业务依赖Kickoff Context/API。
3. 逐页替换标题区、工具栏、表格、状态与浮层的旧视觉；保留业务数据与交互实现。一个页面的主体、Drawer和Modal一起对齐，避免局部改色后仍混用不同密度。
4. 按修改范围对照原型并记录差异；不顺手重写后端、重建专业画布、增加导航或更换UI框架。

批准原型已存在时直接按原型落实；无需再次设计线框或增加与本次页面无关的开发阶段。本次文档更新不代表上述代码迁移已执行。

## 10. 作业平台：Kestra 原生 UI 实施硬规则

### 10.1 当前产品决策与权威依据

- 产品名称固定为 **作业平台**。Flow、Execution是资源术语，保留`/flows`及既有API命名兼容，不把整个模块重新命名为Flows。
- 用户已明确要求**直接复用Kestra开源前端组件、页面组织和UI/UX**，不是只借鉴颜色，也不是用React/shadcn重新画一套相似页面。不得再次以旧文档“不复制源码”为由退回自制界面。
- 固定上游为Kestra `v2.0.7`、commit `49b62a2c820d37e98a1c7b63aa35fd83f960d4ec`。只复用Apache-2.0开源内容，保留LICENSE、来源和修改说明；不将上游locked/demo企业入口冒充可用功能，不替换Keel品牌。
- [替换方案](flows-redesign/KESTRA-UI-REPLACEMENT.md)规定逐页替换、生命周期LC-01～14和上游源组件；[原任务](flows-redesign/keel-flows-module-build-spec.md)及同目录draw.io规定Keel业务覆盖。上游原生UI是实现与交互基准，不再按旧ASCII线框另造布局。
- 当前开发分支、工作区和部署授权以[HANDOFF](../HANDOFF.md)及AGENTS.md为准；不从历史原型工作区继续业务开发。

### 10.2 原生模块与Keel边界

- 保留Keel唯一Sidebar、顶栏、ProjectSwitcher、React Router和身份会话；作业平台挂载独立Vue模块。不增加第二套全局导航、iframe或临时用户入口，不迁移BOM/CMDB等其他模块。
- 表格、筛选、按钮、状态、弹层、多面板编辑器、任务属性、Gantt、日志、变量/输出等优先使用上游原生组件；Keel专属Targets、Quick Run、Agents、审批扩展也用相同原生组件组合。通用字体、色彩、按钮/表格密度和浮层外观通过主题与适配层对齐§2–§6；专业编辑器、Gantt及日志保留原生结构与交互，不为统一视觉另写一套实现。
- 集中Adapter连接Keel API；浏览器不直连Kestra、不携带引擎凭据。项目、权限、目标设备、审批、CMDB稳定ID、通道及维护态约束由Keel保留，后端逐请求授权。
- 上游样式限定在`.keel-kestra`模块作用域；浅/深色跟随Keel主题。修改导入组件标记适配内容，不让全局CSS、弹层、快捷键或布局监听影响其他模块。
- Flow与Execution使用一份URL状态，支持刷新、深链接和前进后退；切项目/卸载时清理请求和订阅。只持久化布局偏好，不在localStorage保存会话、秘密或可变执行范围。

### 10.3 导航与页面信息架构

- 侧栏沿用**作业平台、Executions、Agents**三个已确认入口，不为每项生命周期能力增加一级菜单。
- Flow目录采用原生列表/筛选/列管理/批量动作；创建为主动作，Quick Run为次动作。搜索、排序、分页total和最近执行摘要来自授权服务端查询，不能用已加载数据的本地分页冒充完整目录。
- Flow详情按批准原型固定Overview、Builder、Executions、Revisions、Triggers；依赖、日志、指标、并发放同一标签栏的“更多”。Files、模板、Docs进入编辑器面板，不堆多行Tabs。
- Execution目录提供记录、运行概况、异常/等待保存视图及跨执行日志。只显示实际聚合，不重复全局Dashboard。
- Execution详情按批准原型固定Overview、Targets、Gantt/Tasks、Logs、Variables & Outputs、Audit/Context；更多包含Metrics、Dependencies。每个页面保留独立URL，选择任务/设备/Attempt后联动日志和输出。

### 10.4 编辑器：同一份定义的连续交互

- 直接复用上游多面板编辑器、Monaco、No-code/BlockEditor及Topology；支持分栏、标签切换/关闭、拖动、最大化和布局恢复。默认Visual与Topology并排，YAML随时打开；不再设计固定三栏替代品。
- 节点目录 → 添加/选择节点 → 属性/脚本编辑 → YAML同步 → 校验定位 → 保存Revision → 目标预检 → 执行，必须形成连续路径。只读结构摘要不能称为No-code，普通textarea不能替代Monaco。
- Visual、YAML、Topology、Files及模板共用canonical Flow定义，不维护第二套图数据。不保留“设备步骤/完整编排”两套互相独立的编辑入口。
- 设备任务是Keel受控适配；当前只有串行依赖时，应在真实所属任务内部表达，不画成可任意并行执行的Kestra节点。未知插件参数不能因Visual编辑而丢失。
- 属性与Docs来自实际可用插件/任务Schema；不得用静态少量输入框宣称支持所有Kestra插件。未具备的能力明确说明限制，不使用可点击但无行为的按钮。
- 文件内容/版本、脚本、输入及目标随Revision/Execution冻结；套用模板处理未保存修改，不能保留旧票据、回调或触发器。快捷保存遵守只读、权限和忙状态。
- 脚本入口必须完整可见：新增脚本、导入本地文本脚本、文件列表、Monaco在线编辑、保存和下载。不能以预置文件或普通textarea冒充脚本工作台。脚本草稿在切换面板时保留，未保存内容不得被“在Flow中使用”静默采纳。
- 文件引用与内联快照明确区分：Namespace文件引用产生namespaceFiles/commands，内联使用已保存内容生成script。允许新增脚本任务或明确替换兼容脚本任务，禁止把Log等其他节点静默转换成脚本任务。引擎脚本任务不等于Keel设备执行通道；真实设备操作仍走目标/通道/预检/审批。

### 10.5 执行中心与生命周期

- 按LC-01～14完整纳入状态历史、TaskRun/Attempt、暂停/恢复/终止/重试、变量文件、指标、依赖、跨执行日志、并发队列、触发补跑、源码搜索及历史版本导航；未完成项保留在实施记录，不因主列表能打开就称为完成。
- 故障路径：Execution → 失败TaskRun/目标 → 指定Attempt日志 → 原因/产物 → 失败目标定向重试 → 新Execution；保留父执行和筛选返回路径。
- Kestra引擎状态与设备成功/失败/阻断分别展示；Worker与设备Agent分别建模。不能用引擎SUCCESS覆盖部分设备失败，不能用当前状态推算历史。
- 暂停/继续、终止、失败目标重试、全部重跑、修改输入后新运行是不同操作，确认时冻结项目、Revision、设备集合、输入与审批。权限不等于批准，不直通引擎绕过JobService。
- 日志使用当前Execution SSE/游标查询，支持任务、Attempt、设备、等级、时间与跟随；不加载全量目标日志或在浏览器遍历所有执行拼接跨执行检索。
- Inputs/Outputs先脱敏，文件按授权资源下载。没有真实指标、排队原因、触发历史或依赖证据时显示缺失，不编造趋势、百分比、下次触发时间或故障关系。

### 10.6 视觉与交互验收

作业平台独立高保真原型入口：[原型说明与页面](flows-redesign/prototype/README.md)。使用现有5181供用户先审阅，属于synthetic设计预览，不代表正式组件/API集成完成。

- 1440px及以上桌面优先，紧凑单行标题/动作、筛选栏和高利用率主体；编辑器与执行工作区占主要空间。去掉占据大面积的说明、重复统计卡、卡片嵌套和无意义空白。
- 通用字体、间距、行高、状态、按钮、图标、表格及浮层遵循本文件Kickoff视觉基准，使用上游主题入口或受控作用域样式适配；编辑器/日志的等宽文本、专业布局与原生行为继续保留。验收同时确认组件真实复用及通用视觉一致，不用换色或截图代替功能。
- 同页覆盖loading、empty、error、permission、partial、unknown等适用状态；主要操作有可观察结果，无权限按既定规范禁用并说明原因。
- 检查真实来源组件、许可证、canonical定义同步、URL/主题/项目一致性和BOM/CMDB样式隔离。截图与关键交互按实际变更定向验证，不重复全仓测试。
- UI复用、后端能力、环境发布、真实设备验收分别记录；浏览器synthetic数据只证明对应UI行为。不得再把软件缺口写成“只等真机”。
