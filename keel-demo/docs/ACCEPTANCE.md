# ACCEPTANCE.md — 功能验收契约

> 验收依据是可复现的行为与证据。未执行的测试标记 `NOT RUN`；mock/simulator 验收不等于真机验收。阈值和规则引用 PRD，不在此复制第二份数值事实源。

## 1. 总体验收原则
- 每个验收项记录：ID、前置条件、步骤/输入、预期结果、证据、状态（PASS/FAIL/BLOCKED/NOT RUN）。
- `PASS` 必须有测试结果或可追溯证据；截图只能证明 UI 呈现，不能单独证明后端规则正确。
- 业务规则以 PRD 为准；状态和字段与 SYSTEM-DESIGN、DATA-DICTIONARY、OpenAPI 一致。

## 5. 前端验收
- 所有异步动作展示 loading、成功、失败、空状态；长任务显示后端状态和可恢复错误。
- 表格筛选/排序/分页/选择行为一致；批量操作显示准确目标数量、跨页选择范围和排除项。
- BOM 审核能在同一工作流查看原始来源、标准字段、转换结果、规则错误和修正记录。
- BLOCK/WARN/INFO 视觉与操作语义区分；关键阻断不可只用颜色表达。
- 危险操作确认显示项目、目标、动作和版本；前端确认后服务端仍重新校验。
- 组件采用 React + TypeScript + shadcn/ui；页面不得用不可操作的静态按钮伪装已实现功能。

## 6. 发布门槛
- P0 BOM 主链路验收全部通过后，才可宣称 BOM 导入 MVP 完成。
- 关键数据/安全/门禁测试 FAIL 时禁止发布对应能力。
- simulator 结果和真机 PoC 结果分开记录。
- 性能要求按 PRD 的负载与计时口径实测；没有测试结果不得标记通过。

## 6. 前端先行与全量 Mock 验收

- 所有一级导航均可访问，无死链/空白页；所有主按钮有真实交互反馈。
- 每个页面通过统一 API provider 获取数据；组件中没有散落的大段业务 mock 常量。
- 每个模块至少有正常、空、加载、错误、权限拒绝、部分失败/unknown 状态。
- Flow 可演示创建/编辑、选择纳管服务器/交换机、脚本参数、定时频率、运行、状态更新、日志、输出、暂停/继续/终止/重试；所有 mock 明确标识。
- Execution 页面展示生命周期、触发频率、开始/结束、耗时、目标总数、成功/失败/运行中数量、attempt、exit code、日志和产物。
- CMDB 从 BOM 导入任务开始可查看来源、实体关系和时间线，并能展示 `projection_pending`/重试失败。
- 关键页面在 1440×900 和 1280px 宽度完成视觉检查，按 UI-REFERENCE 的标准提供截图或检查记录。

## Rack Diagram 验收

- 从确认 BOM revision 生成图纸版本，来源 BOM/型号/规则/生成器版本可追溯。
- 机柜高度、U 位、设备高度明确时正确落位；缺失时显示未分配/待审核，不推断为实际布局。
- U 位冲突、越界、重复设备、未知高度、无效机柜引用和线缆端点问题可定位到源数据/实体。
- 再生成显示结构化 diff，保留人工覆盖；发布版本不可原地覆盖。
- 前/后视图、full-depth 设备、空 U 折叠、键盘操作、撤销/重做、多机柜导航和 SVG/PNG/PDF 导出正常。
- 布局变更和发布进入 CMDB 时间线与审计；敏感凭据不得出现在画布、接口普通响应、Mock 和导出中。
