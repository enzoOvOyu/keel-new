# TEST-STRATEGY.md — 测试与仿真策略

## 1. 原则
- 以 PRD 的业务规则与 `ACCEPTANCE.md` 为验收依据；测试验证契约，不替代契约。
- 只测试变更影响范围及其直接依赖；不重复执行无关全仓测试。
- 真实设备未接入时使用明确 simulator/mock 和 golden fixtures。不可模拟的能力必须返回 `unknown/unsupported`，不得伪造 PASS。
- 测试数据不得包含真实客户凭据、私钥或未脱敏拓扑。

## 2. 测试层级

| 层级 | 目标 | 最低覆盖范围 |
|---|---|---|
| Go 单元测试 | 纯逻辑、规则和状态转换 | BOM 身份/摘要/幂等、字段转换、校验规则、权限判定、门禁、状态机 |
| 前端单元/组件测试 | 表单与交互状态 | 上传状态、问题筛选、映射确认、阻断提示、危险操作确认、空/错/加载态 |
| API 契约测试 | 请求/响应与 OpenAPI 一致 | 成功/错误结构、枚举、分页、授权、幂等、异步 Job 状态 |
| 集成测试 | 数据库/对象存储/队列协作 | 事务提交、回滚、Outbox、重复事件、文件引用、审计、版本并发冲突 |
| E2E | 关键用户路径 | 原始开局表→审核→标准 BOM→提交；生产变更审批流程的模拟路径；门禁阻断 |
| Simulator/golden | 设备协议与输出契约 | SSH/CLI/NVUE、LLDP、DDM、日志、计数器、异常注入和 `unknown` 降级 |
| PoC/真机验证 | 验证设备/厂商实际行为 | 仅在批准的环境、窗口和执行计划中进行，留存证据；不得把 mock 结果算作真机验证 |

## 3. BOM 智能导入测试矩阵

必须建立人工核验的标准答案集，覆盖：
- 不同人员、不同工作簿、Sheet 名、表头名称和列顺序；
- 多行表头、合并单元格、重复表头、空行、隐藏 Sheet、公式缓存缺失；
- 已知别名、未知列、同名异义字段、单位不一致、占位符、空值；
- 重复 SN/MAC、未知型号、端口不存在、线缆端点歧义、breakout 不匹配、光模块速率冲突；
- 同批次同摘要重复导入、同批次异摘要冲突、提交期间 draft revision 被修改；
- AI API 超时、限流、格式错误、无结果或置信度低；
- 恶意/超限文件、宏、外链、压缩包路径穿越和明文凭据。

每个样本应保存：脱敏原始文件、人工标准答案、样本来源类别、预期问题/级别、评测版本。真实文件不可提交到公共仓库；无真实样本时使用明确标注的合成样本，不得声称代表真实准确率。

## 4. 必须测试的业务不变式
- AI 输出不能直接提交正式 BOM；模型输出必须经过 Schema、规则校验和审核策略。
- 未知列进入问题清单，不得静默丢弃。
- 任一 BLOCK 未清零时提交失败；关键身份/端口/链路歧义不能自动放行。
- 服务器和网络标准包同批次、同事务提交；事务失败不留下部分正式 BOM。
- 同批次同摘要幂等；同批次异摘要冲突。
- 过期、缺失或 unknown 的关键证据不能转成 PASS。
- 未审批 PushJob 不能执行；审批后目标或计划变更必须重新审批。
- 外部副作用超时但结果未知时先对账，不盲目重试。
- 服务端授权覆盖 REST、导出、文件下载、后台任务与实时订阅。

## 5. 设备 simulator 契约
- 仿真命令输出以版本化 golden files 固化；差异必须审查，不能为让测试通过而自动刷新基线。
- 每个能力声明 `supported/unsupported/unknown`，缺失数据不得默认正常。
- 异常注入覆盖超时、拒绝认证、部分输出、命令退出码非零、链路 flapping、LLDP 缺失、DDM 越限、计数器不支持和设备状态与意图不一致。
- 设备型号/NOS 版本差异必须由适配器和契约样本表示，业务代码不猜测未登记的命令或计数器。

## 6. 性能测试
- 性能指标只在 PRD 明确的负载、硬件、并发、连接预热和计时边界下判定。
- 10k 目标批量作业、10 万端口对比对等规模目标，必须记录数据量、并发、运行环境、P50/P95、失败率和资源使用。
- 未实际运行的性能测试标记 `NOT RUN`；不得用理论算式替代测量。

## 7. 交付报告
每次实现报告只列：受影响测试、实际命令与结果、未运行项及原因、真实阻塞。测试失败先定位根因，只重跑必要范围。不得降低断言或删除测试来掩盖业务缺陷。

## 6. Frontend-first、CMDB 与 Flow 验证

- 前端 mock fixtures 必须通过 OpenAPI schema 校验；场景固定、可复现，不用随机状态。
- Flow 测试覆盖：目标快照冻结、服务器/交换机目标类型、频率与时区、执行状态生命周期、日志游标、retry attempt、pause/resume/kill、partial failure、result_unknown 对账。
- CMDB 测试覆盖：BOM 导入事件是起点；BOM/Device/Port/Cable/Execution/Gate/Issue/Approval 等事件均生成或更新实体关系；重复消费不重复建记录；失败可重放；投影延迟有状态；权限过滤适用于实体/关系/timeline。
- Excel 导入测试覆盖：资产清单、OOB 地址表、P2P 双端布线表、分片连接表、空白继承、布局网格、汇总 reconciliation、未知列和敏感列。
- 安全回归必须断言密码/令牌在日志、API 响应、CMDB、AI payload、mock fixture、导出文件中的出现次数为 0。
- 只跑受变更影响的测试；前端 mock 阶段不要求真实 Go 服务或真机在线。

## Rack Diagram 测试

- Golden tests：固定 BOM/model/policy 输入产生固定布局 JSON 与 `content_hash`。
- 规则测试：U 位越界/重叠、缺高度、full-depth 前后面重复、重复设备、无效线缆端点、未分配设备。
- 回归测试：重生成保留人工覆盖、revision diff 正确、失败生成不影响已发布图、并发修改通过 If-Match 检测冲突。
- 前端测试：缩放/平移/正反面、拖动预览、键盘替代操作、撤销/重做、问题筛选、发布确认和导出错误状态。
- 安全测试：图纸及导出不含账号、密码、token、私钥；项目隔离适用于图纸、设备、关系、导出和时间线。
